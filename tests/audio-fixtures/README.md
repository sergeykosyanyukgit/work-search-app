# Синтетические аудиофикстуры

`en-question.wav` и `ru-question.wav` созданы для Work Search 23 октября 2026 из собственных текстов `en-question.txt` и `ru-question.txt`. Оба файла распространяются по корневой [MIT](../../LICENSE).

Звук получен локально eSpeak NG 1.52.0, встроенными формантными голосами `en-us` и `ru`, без MBROLA, Windows SAPI и записей человека. Скорость — 130 слов/мин, пауза между словами `-g 5`. [Автор eSpeak пояснил](https://sourceforge.net/p/espeak/discussion/538920/thread/c6944a60/), что GPL программы не распространяется на сгенерированные WAV. Сам синтезатор и его данные не включены в Work Search; условия распространения программы остаются GPL.

| `en-question.wav` | mono PCM16, 16 kHz | `e821de7ff3cea0e08f718cab836269e00435373db12f643fdbcba1f73e8b0dd3` |
| `ru-question.wav` | mono PCM16, 16 kHz | `c206d0269d5b5857196edba93eeb01657dd18de8e552374251b60517747af61e` |

Для повторной генерации используйте [официальный eSpeak NG 1.52.0](https://github.com/espeak-ng/espeak-ng/releases/tag/1.52.0) и Node:

```powershell
node scripts/generate-audio-fixtures.mjs 'C:\path\to\espeak-ng.exe'
```

Рядом с executable ожидается `espeak-ng-data`. Использованный официальный MSI имеет SHA256 `7f673c709ea5dd579d3b5ebb98688cc575328a6ab7438d2bc405b88cedaeafb9`; в этой работе он распакован в `.cache`, без установки в Windows. Генератор направляет звук в WAV, затем преобразует его в PCM16/16 kHz. Он не открывает микрофон, не воспроизводит звук и не обращается к AI.

Обычные тесты читают готовые WAV и не требуют eSpeak. Native STT проверяет ключевые слова и отмену распознавания; синтетическая речь не заменяет приёмку качества на реальных голосах и устройствах. Для русской формантной речи допускается написание «ассинхронность» с удвоенной согласной, но «синхронность» без отрицательного префикса тест не проходит.

Ранее использовавшиеся JFK sample и Windows Irina WAV удалены из подготовленной локальной истории. Публикуемый коммит содержит только указанные выше синтетические WAV; `pnpm check:publication` проверяет их SHA256 и отсутствие прежних blobs во всех локальных refs. Очистка GitHub требует отдельной отправки очищенной ветки по [инструкции](../../docs/publication.md).
