# React UI Work Search

Найди нужный экран в `src/renderer/Overlay.tsx` или `Settings.tsx`, общий элемент в `components.tsx`, состояние/команды в `hooks.ts`, стили в `styles.css`. [IPC-контракт](../../../src/shared/ipc.ts) уже задает доступные действия.

## Раздели состояние перед правкой

| Вид данных | Источник | Что проверить |
| --- | --- | --- |
| Вопросы, очередь, соединение, STT, история | AppSnapshot | Отрисовка следует новым snapshots и смене interview.id |
| Черновик настроек/токена/вопроса | Локальный React state | Новый snapshot не стирает несохраненный ввод |
| Действие в полете | useCommands.pending | Повторный клик не отправляет ту же команду дважды |
| Выбранный провайдер и провайдер активного интервью | Разные поля snapshot | Сохранение настроек не создает видимость смены текущего транспорта |

Не создавай вторую бизнес-очередь в React. Если команды нет в контракте, согласуй ее с владельцем IPC до UI-интеграции.

## Сохрани поведение экрана

Для изменения ответа проверь первый непустой текст до completed, длинный Markdown/код, прокрутку и переключение вопросов. Отсутствующая метрика не равна нулю. Ссылки/изображения из удаленного Markdown не должны загружать ресурсы; не подключай raw HTML.

Для формы настроек проверь обновление статусов при несохраненном вводе, явное сохранение и отсутствие повторной отправки неизмененного токена. При сохранении bounds берутся из свежего snapshot. Пустое поле токена означает отсутствие token в команде, а удаление выполняется отдельным действием. Начальный async snapshot не должен перезаписать уже полученное subscription update. Для истории проверь удаление именно выбранного интервью и сохранение подтверждения. Для захвата — состояния starting/stopping и заполненную очередь без блокировки нужной остановки записи.

Переиспользуй существующие компоненты, lucide-react, CSS-переменные и русские подписи. Визуально проверь измененный экран при узком окне, увеличенном шрифте, keyboard focus и длинном содержимом; не ограничивайся статическим happy path. Для маленькой правки выбирай только связанные состояния.

## Проверка

`pnpm typecheck`; после `pnpm build` запусти подходящие сценарии `pnpm exec playwright test e2e/ui-renderer.spec.ts`. Тест использует реальный собранный renderer и подмененный `window.desktop` с управляемыми snapshots.

Сделай визуальную проверку доступным браузерным инструментом или существующим Playwright. Если используешь computer-use skill, соблюдай доступные в текущей сессии поверхности. Отсутствие GUI не заменяй утверждением «визуально проверено»; укажи, какие проверки фактически доступны. Условия Chromium — в [AGENTS.md](../../../AGENTS.md).
