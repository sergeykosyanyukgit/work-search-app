# SQLite и совместимость данных

Прочитай `src/adapters/storage/sqlite-store.ts`, `diagnostics.ts`, `src/domain/ports.ts` и [tests/storage.test.ts](../../../tests/storage.test.ts). Сверяй актуальный user_version с исходниками.

## Реши, нужна ли миграция

Схема хранит JSON-содержимое в зашифрованных BLOB. Новое необязательное поле с корректным default при чтении не всегда требует SQL-миграции. Новое обязательное поле, изменение индексов/связей или несовместимая семантика требует стратегии чтения старых записей и, при необходимости, транзакционного преобразования.

Проверь потребителей: SettingsSchema, Interview/Question, provider routing, PendingCommand и history summaries. Не меняй идентичность команды или вопроса ради нового поля.

## Для изменения схемы/формата

1. Подготовь искусственную старую БД во временном каталоге, используй тестовый StringCipher. Сохрани разные интервью, ревизии, секрет, частичный ответ и ожидающую команду.
2. Преобразуй записи в одной транзакции; версию меняй только вместе с успешной миграцией. Если требуется plaintext для преобразования, он существует только в памяти, а запись снова проходит cipher.
3. Сравни логически расшифрованное содержимое до/после, ID, порядок и связи. Не требуй равенства ciphertext после повторного шифрования: cipher может использовать случайный IV.
4. Проверь повторное открытие и отказ в середине миграции. Старые данные и версия при rollback остаются согласованными; неподдерживаемая будущая версия явно отклоняется.

Для текущего формата проверь сохранение outbox до terminal, атомарность answer/cursor и каскадное удаление связанных вопросов/команд. Не удаляй историю, чтобы миграция начала проходить.

## Диагностика и проверки

`diagnostics.ts` использует разрешенные поля. Новый диагностический параметр проверяй тестом содержимого файла; исходный текст, токены, звук, endpoint с секретом и raw RPC не должны попадать в него. Для latency отсутствие этапа означает отсутствие измерения, а не ноль.

Запусти `pnpm typecheck` и `pnpm exec vitest run tests/storage.test.ts tests/diagnostics.test.ts` при Node ABI. Тестовый cipher не доказывает работу DPAPI: production safeStorage проверяется отдельным Electron packaged smoke. Порядок ABI и ограничение тестовых профилей — в [AGENTS.md](../../../AGENTS.md).
