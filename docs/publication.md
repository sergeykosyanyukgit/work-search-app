# Публичная выкладка Work Search

Исходники подготовлены под MIT, правила участия описаны в [CONTRIBUTING](../CONTRIBUTING.md), приватное сообщение об уязвимости — в [SECURITY](../SECURITY.md). Публикация исходников и выпуск установщика — отдельные действия.

## Состав исходников

В публикуемую историю входят только проверенные синтетические `en-question.wav` и `ru-question.wav`. Прежние JFK/Irina WAV исключены из новой локальной истории. Исторические benchmark-результаты с прежними названиями fixtures сохранены как исторические сведения, без соответствующих аудиофайлов.

Проверка перед отправкой:

```powershell
pnpm check:publication
pnpm audit --audit-level high
git status --short
```

`check:publication` проверяет все локальные refs на прежние WAV blobs, точные SHA256 двух разрешённых записей и отсутствие runtime/build/credential-файлов в коммите. Это не замена поиску секретов. CI отдельно запускает Gitleaks 8.30.1 с проверенным SHA256, redaction и полной доступной историей; локальная проверка очищенного коммита выполнена тем же сканером.

Не отправляйте `.cache`, Git bundle резервной копии, архивы исходного рабочего дерева, модели, пользовательские базы и готовые бинарники как часть исходников. `.gitignore` исключает их; `git push --mirror` и публикация архива всей папки проекта для этой операции не подходят. Публикуйте явно выбранную ветку либо создавайте архив через `git archive` из очищенного коммита.

## Замена прежней ветки на GitHub

Очистка локальной истории не удаляет прежние коммиты с сервера. В исходном клоне сохранена приватная резервная копия старой истории и ранее проверенное значение remote master. Перед заменой согласуйте её с участниками: после rewrite им потребуется новый clone или осознанная перенастройка своих веток.

Для существующего remote используйте явный lease с **ранее записанным** SHA ветки до очистки, а не значение, автоматически обновлённое fetch. Пример с placeholder, который нужно заменить проверенным значением:

```powershell
git push --force-with-lease=refs/heads/master:PREVIOUS_REMOTE_COMMIT origin master:master
```

Если remote изменился, команда должна отказать. Не обходите отказ через `--force`: сначала разберите новые изменения. Служебные refs, теги и другие ветки не нужно отправлять автоматически. Для нового пустого репозитория достаточно обычного `git push -u origin master`.

После отправки сделайте свежий clone с GitHub и выполните `pnpm check:publication`, Gitleaks и Windows CI. Старые PR refs, forks, caches и чужие clones могут сохранять прежние объекты после force-push. При наличии таких копий отдельно согласуйте очистку с владельцами и GitHub; новая ветка не гарантирует удаления всех серверных копий.

## Настройки GitHub

- Дождитесь успешных `checks`, `dependencies` и `secrets` в workflow Windows checks.
- Включите Private vulnerability reporting или объявите действующий закрытый канал по SECURITY.md.
- Включите Dependabot alerts и защиту основной ветки с обязательными CI-проверками. После согласованной замены истории запретите обычные force-push.
- Перед изменением видимости проверьте README, MIT, доступы участников и содержимое свежего clone. Не связывайте изменение видимости с автоматическим запуском provision/benchmark: эти команды обращаются к внешним сервисам.

## Бинарный выпуск

Перед загрузкой installer выполните свежие `pnpm run dist` и `pnpm test:packaged`, проверьте размер/SHA256, лицензионные условия [сторонних компонентов](../THIRD_PARTY_NOTICES.md) и установку на чистой Windows. Изменение notices/package metadata требует пересборки старого артефакта. Право издателя распространять VC++ runtime подтверждается его лицензией Microsoft, а не подписью бинарника.

Code signing и auto-update пока не настроены. Результат скрытия окна при демонстрации экрана, физический loopback и реальные AI-провайдеры проверяются отдельно. Предыдущие [аудит](audit-2026-10-23.md) и [исправления](audit-remediation-2026-10-23.md) содержат точный объём проведённых проверок.
