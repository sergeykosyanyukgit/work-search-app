# Измерение времени ответа

Под каждым новым ответом показаны «Первый текст» и «Готово». Отсчет начинается при отправке ручного вопроса или завершении записи; время, пока пользователь записывает вопрос, исключено. Первый текст означает первый непустой блок `agent_message`, реально полученный приложением. Это не служебное событие начала запроса и не рассуждения модели. Если сервис прислал только готовый ответ, оба времени будут близки.

Разверните строку времени для этапов: распознавание, очередь приложения, ожидание подключения, AI до первого текста и AI до завершения. AI включает сеть, очередь сервиса и генерацию. Общие значения измерены локальным монотонным таймером, без сравнения часов компьютера и сервера. При разрыве соединения в общую длительность входит восстановление. Для запроса, восстановленного после перезапуска приложения, новые значения с нуля не подставляются.

Поле `Question.latency` сохраняется вместе с зашифрованной историей, миграция SQLite не нужна. В `userData/diagnostics.log` события `AI_COMPLETED`, `AI_FAILED` и `AI_CANCELLED` содержат только ID вопроса и числовые длительности `sttMs`, `queueMs`, `connectionMs`, `aiFirstAnswerMs`, `aiTotalMs`, `firstAnswerMs`, `totalMs`. Текст, токен и URL в диагностический файл не передаются. Отсутствующее значение означает, что этап не измерен; это не нулевая задержка.

Подключение к codex-manager прогревается во время записи, после явного действия пользователя. Адаптер сохраняет ответ и курсор события атомарно; UI публикует уже сохраненный снимок без повторной записи и чтения всей истории на каждом обновлении. Одновременное завершение handshake и отправка вопроса больше не доставляют одну команду дважды. Повтор после reconnect или отказа из-за еще занятой сессии сохраняет исходный `clientRequestId`.

Для сравнения версий используйте одинаковую модель, язык, профиль и длину ответа; отдельно измеряйте первый вопрос новой сессии и последующие вопросы. Сравнивайте медиану и p95 минимум нескольких последовательных запросов. Показатели сервера позволяют отделить его очередь и генерацию от клиентского пути. Цель 1–2 секунды следует проверять отдельно для первого текста и полного ответа. Она не гарантирована для произвольной длины ответа и CPU-распознавания двух аудиодорожек; системная и микрофонная дорожки Whisper small обрабатываются последовательно.

## Рабочий сервер, 11 сентября 2026

Сервис обновлен, опубликован `interview-assistant@2`; модель осталась `gpt-5.6-sol`, reasoning `low`. Постоянный Codex App Server передает текст по мере генерации. Новый профиль просит короткий ответ по умолчанию; явные просьбы о подробностях или коде поддерживаются. Для его использования начните **новое интервью**: сохраненная сессия V1 сохраняет прежнюю конфигурацию. Действующий токен и квоты клиента не изменены.

На шести одинаковых коротких вопросах в двух новых сессиях первый текст пришел за **1,64–3,57 с**, медиана **2,16 с**; полный ответ — **2,69–4,64 с**, медиана **3,25 с**. В первой серии медиана первого текста была **2,18 с**. Исходная версия: медианы **6,60 / 6,85 с**. Замер выполнялся из контейнера manager через публичный WSS: учитывает прокси и доставку событий, исключает сеть Windows-клиента, отрисовку и STT. Изменение длины ответа также влияет на результат. Выборка небольшая, это не верхняя граница времени.

Отчеты: [исходная версия](benchmarks/server-baseline-2026-09-11.json), [сравнение V1/V2](benchmarks/server-production-2026-09-11.json), [повтор V2](benchmarks/server-production-repeat-2026-09-11.json). Изолированное сравнение Luna дало медианы 1,60 / 2,73 с, но профиль оставлен на Sol; это не общий тест качества моделей.

Проверки отмены, следующего запроса, переподключения без повторной отправки и сохранения истории прошли. Отдельное ограничение: после отмены длинного ответа два теста дали **25,5–28,4 с** до следующего полного ответа. [Подробный повтор](benchmarks/server-streaming-smoke-repeat-2026-09-11.json) локализовал 26,34 с внутри Codex после начала генерации; очередь и запуск вместе заняли 52 мс. Точная причина внутри модели/ее транспорта не установлена. Отмена и продолжение работают, но эта задержка не устранена.

## Локальный замер Whisper, 11 сентября 2026

Windows, Ryzen 5 8600G (6 физических / 12 логических ядер), whisper.cpp 1.9.2, исходная multilingual `ggml-small.bin`, CPU, `language:auto`. Использованы только репозиторные фикстуры; пользовательские записи не читались. Готовность нового процесса, включая проверку ресурсов и загрузку модели: 0,86–1,07 с. Это холодный процесс при обычном файловом кеше ОС, а не загрузка с выключенного компьютера.

Полные числовые результаты: [stt-2026-09-11.json](benchmarks/stt-2026-09-11.json).

| Настройка | RU, аудио 8,705 с, два запуска | EN, аудио 11 с, два запуска |
|---|---|---|
| 4 потока, прежнее значение | 5,602 / 5,286 с | 5,358 / 5,189 с |
| 6 потоков | 4,317 / 4,406 с | 4,275 / 4,335 с |
| 8 потоков | 3,848 / 4,054 с | 3,986 / 3,841 с |
| 12 потоков | 3,783 / 3,616 с | 3,525 / 3,526 с |

Для версии 0.1.2 выбран предел 8 потоков на процессорах с более чем 8 логическими CPU. Число потоков не превышает `logical CPU − 4`; на меньших процессорах сохранен прежний предел 4. Это ограничение параллелизма, а не резервирование CPU по affinity. Модель, язык, температура и параметры декодирования остались прежними. Повторное сравнение 4 → 8 дало RU 5,711 → 3,915 с и EN 5,434 → 3,860 с; хеши нормализованного распознанного текста совпали для обеих фикстур. Это проверка двух образцов, не общий тест качества распознавания.

Время STT сократилось примерно на 27% в первой серии; даже оно само превышает цель 1–2 секунды. Для такой полной задержки голосового сценария потребуется отдельное изменение подхода: распознавание во время записи, другая модель или GPU. Эти варианты не включены в текущую версию и требуют проверки качества.

На этих же образцах явный выбор языка в существующих настройках дополнительно сокращает время: при 8 потоках RU `ru` — 2,179 с, EN `en` — 2,129 с вместо автоматического определения 3,915 / 3,860 с. Хеши текста совпали. Если язык интервью известен, выберите его перед записью. Значение `auto` по умолчанию сохранено: принудительный язык может ухудшить распознавание, когда собеседник переходит на другой язык.

## Локальный Codex, Windows, версия 0.1.4 — 12 сентября 2026

Упакованное приложение, gpt-5.6-sol, low, стандартная скорость, CLI 0.154.0-alpha.6.2. Пять одинаково коротких технических вопросов; без STT.

| Запрос | Первый текст от отправки | Полный ответ |
|---|---:|---:|
| Первый в новом интервью | 10,371 с | 12,828 с |
| Последующие четыре, медиана | 1,956 с | 4,438 с |
| Последующие четыре, диапазон | 1,711–2,244 с | 4,229–4,822 с |

В первом запросе открытие локального подключения заняло 1,104 с, от отправки в Codex до первого текста — 9,265 с. Последующие запросы использовали готовый процесс (connectionMs=0). Причина медленного первого ответа внутри Codex не установлена; запуск одного процесса заранее не гарантирует прогрев генерации модели.

Живое сравнение с облачным codex-manager **не выполнено**: в стандартном профиле Windows не найден сохранённый клиентский токен. Облачный режим в пакете проверен на тестовом сервере существующего протокола. Ранее опубликованные серверные 2,18 с имеют другой путь измерения и не являются прямым сравнением с этой серией. [Сырые данные](benchmarks/providers-windows-0.1.4.json).

По завершении локальной серии новых процессов Codex не осталось; все ранее работавшие экземпляры продолжили работу.
