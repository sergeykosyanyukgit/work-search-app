# Skills для разработки Work Search

Skill описывает повторяемую процедуру: как провести IPC-команду через слои, воспроизвести потерю acknowledgement или проверить миграцию. Субагент определяет исполнителя и область ответственности. Одна роль может использовать несколько skills, а один skill полезен разработчику и проверяющему.

Проектные skills находятся в [`.agents/skills/`](../.agents/skills/). Это стандартный каталог обнаружения навыков Codex в репозитории; установка npm-пакетов для их подключения не нужна. [Официальная документация](https://learn.chatgpt.com/docs/build-skills) описывает обнаружение и вызов.

## Проектный набор

| Skill | Что помогает делать | Основные роли |
| --- | --- | --- |
| [work-search-feature](../.agents/skills/work-search-feature/SKILL.md) | Проследить команду через слои, изменить FIFO/состояния, проверить отмену и смену интервью | architect, backend |
| [work-search-electron-ipc](../.agents/skills/work-search-electron-ipc/SKILL.md) | Расширить строгий IPC, сохранить проверку sender/frame, правильно обработать окна и hotkeys | electron |
| [work-search-react-ui](../.agents/skills/work-search-react-ui/SKILL.md) | Сохранить черновики при snapshots, реализовать UI-состояния, проверить Markdown и доступность | frontend |
| [work-search-ai-recovery](../.agents/skills/work-search-ai-recovery/SKILL.md) | Воспроизвести сбой доставки, сверить cloud/local историю, сохранить outbox и избежать повторной генерации | ai_integrations, backend |
| [work-search-audio-stt](../.agents/skills/work-search-audio-stt/SKILL.md) | Локализовать ошибку capture/PCM/Whisper, проверить временные метки и измерить скорость на fixtures | audio_stt |
| [work-search-sqlite](../.agents/skills/work-search-sqlite/SKILL.md) | Решить необходимость миграции, проверить rollback, шифрование, историю и формат диагностики | storage |
| [work-search-testing](../.agents/skills/work-search-testing/SKILL.md) | Выбрать тестовый уровень, проверить среду, согласовать ABI и отделить mock/native/live проверки | qa и исполнители |
| [work-search-release](../.agents/skills/work-search-release/SKILL.md) | Подготовить build/pack/dist, проверить ресурсы и smoke, зафиксировать артефакт и ограничения | release |

`reviewer` использует профильный skill для критериев ревью и `work-search-testing` для оценки доказательств проверки. `architect` использует процедуры анализа. Применение skill не меняет режим чтения этих ролей.

В каждом skill есть `SKILL.md` с точным условием применения и `agents/openai.yaml` с названием и коротким описанием для интерфейса Codex. Автоматический выбор оставлен включенным по умолчанию. Skills загружаются по задаче, поэтому простой CSS-фикс не требует чтения всех процедур.

## Как подключены

- Каталог `.agents/skills` обеспечивает обнаружение в этом репозитории.
- [AGENTS.md](../AGENTS.md) связывает виды задач с навыками.
- В [конфигурациях десяти субагентов](../.codex/agents/) указаны основные skills и пути к их инструкциям. Остальные навыки выбираются при необходимости по слою.
- `.codex/config.toml` сохраняет прежние настройки агентов. Дополнительные `skills.config` не нужны для стандартного обнаружения; модель, права и глобальные настройки пользователя не переопределены.

Открой новый чат Codex в корне проекта, чтобы обновились определения субагентов. Skills обычно обнаруживаются автоматически; если список не обновился, перезапусти клиент. В CLI/IDE можно использовать `$имя-навыка`, в интерфейсе с селектором навыков — выбрать его через доступный список.

Примеры:

> Используй $work-search-react-ui: исправь потерю введенных настроек при новом snapshot и проверь сценарий в browser E2E.

> Используй $work-search-ai-recovery: воспроизведи потерю acknowledgement и убедись, что после восстановления не отправляется второй turn/start.

> Поручи storage применить $work-search-sqlite для нового обязательного поля интервью; qa пусть проверит миграцию и повторное открытие.

> Используй $work-search-release: собери Windows x64 пакет и проверь packaged smoke в отдельном профиле.

## Проверка среды

Из корня проекта:

```powershell
node .agents/skills/work-search-testing/scripts/preflight.mjs
```

Скрипт выводит версию Node/ABI, ожидаемый packageManager, наличие pnpm в PATH и локальных пакетов, результат открытия SQLite в памяти, наличие сборочных файлов и включенные opt-in флаги. Значения токенов и пути пользовательской модели не выводятся. Скрипт ничего не устанавливает, не меняет ABI, не запускает Electron/сервис/захват и не открывает пользовательскую историю.

Успешное выполнение preflight означает получение диагностического отчета, а не готовность всех тестов. Наличие файлов не подтверждает свежесть сборки, правильные хеши ресурсов или установленный Chromium. Версия pnpm не запускается и не проверяется этим скриптом.

В навыках учтено, что полная `test:e2e` включает browser UI, локальный native E2E запускает пакет, а inherited RUN_LOCAL_CODEX может включить live-запросы в обычном `pnpm test`. Preview provision-скрипта без `--apply` обновляет серверные квоты через POST; для локальной проверки используется его отдельный тест с mock API.

## Уже доступные общие skills

В текущем окружении установлены следующие дополняющие навыки. Они используются по назначению и не копируются в репозиторий; на другой машине их наличие зависит от установки Codex/plugins.

| Skill | Когда нужен проекту |
| --- | --- |
| `openai-docs` | Проверить текущую версию Codex App Server/RPC, настройку моделей и самих агентов/skills |
| `computer-use:computer-use` | Визуально проверить интерфейс через доступные инструменты управления браузером/приложением; прямые Playwright-тесты работают отдельно |
| `security-best-practices` | По явному запросу дать рекомендации по безопасной реализации TypeScript/React |
| `codex-security:security-diff-scan` | По запросу проверить security конкретного diff/PR |
| `codex-security:security-scan` | По запросу провести security-аудит репозитория или пути |
| `skill-creator` | Поддерживать и уточнять этот набор skills |

Изменение обычного IPC или React-кода само по себе не запускает полный security-аудит. При работе с Codex API основной источник — официальная документация и фактическая версия runtime. Проектные skills не требуют новых MCP-подключений или внешних учетных записей.
